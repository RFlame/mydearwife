# 《零食叮叮咚》游戏设计与实现说明（MVP v1.8）

> 当前版本：固定 90° 左屏外篮口撒落 + 整桌自由聚堆自动称重 + 单击远处同款迁移 + 商品独立等比尺寸 + 3～10 款订单曲线。
>
> 美术方向：**复古国潮小卖部 + 一体式电子秤**，保留 LED 数字滚动、价签打印和收银音效。
>
> 引擎：Godot 4.7.2 · Compatibility 渲染器 · Web 优先 · 20 关 MVP。

---

## 1. 游戏概述

**一句话概念**：在高位俯视的收银工作台前接待顾客，让零食从左屏外购物篮口撒到桌面，通过拖动和单击把同款聚成不受异款接触的完整堆，自动完成称重、打印价签、装袋和结账。

| 项目 | 内容 |
|---|---|
| 品类 | 解压整理 + 分拣 + 轻经营 |
| 核心情绪 | 乱到齐、聚堆节奏、清空桌面完成感、收银 ASMR |
| 操作 | 竖屏单击与自由拖动 |
| 店名 | 零食叮叮咚（原创品牌，不使用真实门店品牌） |

### 核心循环

顾客排队 → 左屏外篮口撒落 → 拖动整理或单击迁移同款 → 同款全部连通且不与异款接触 → 整堆自动飞入电子秤 → LED、价签和装袋反馈 → 当前顾客桌面与批次清空后结账 → 下一位顾客 → 完成整关。

**没有三连、固定分拣区、区域退货、手动 POS 称重或任意位置双击结算。** 同款不要求凑满三件；只要该种商品在当前顾客订单中的全部未结算物品形成一个合格连通堆，就按实际件数自动称重。

### 外循环

营业赚金币 → 升级电子秤速度 → 解锁新零食与顾客图鉴 → 挑战后续关卡和不同难度。旧台位、吸附与冻结字段只为核心和存档兼容保留，正常界面没有对应操作入口。

## 2. 核心规则

### 2.1 顾客与逐客订单

- 每关由 `customers` 位顾客组成，顶部显示当前进度；后续顾客使用各自原创头像排队。
- 当前有 **12 位独立角色**，拥有唯一 ID、姓名、头像、性格、简介、台词及耐心/连击窗口修正；同关队列不重复。
- 每位顾客在开局时独立预计算轻量 manifest。`order_rng = seed + 104729` 决定订单，`layout_rng = seed` 决定落点，后续 `generate()` 只补 UID、角度、层序和坐标，不增删物品。
- 普通款每种随机 **1～10 件**；测试局可固定为 1～10 件。巨大款从当客已选种类中取 0～2 种，每种 1～2 件，并替换同款普通包装，不额外增加种类。
- 整关 `total_items` 是所有顾客 manifest 长度之和，不再用首客件数乘顾客数，也不由旧 `items` 字段决定正式订单总量。
- 当前顾客的桌面、活动批次、FIFO 等待队列和兼容秤台全部清空后才换客；最后一位完成后进入结果页。
- 换客清零当前连击，保留整关最佳连击；倒货和换客期间锁输入并暂停耐心。

### 2.2 篮口撒落与桌面坐标

- 篮体位于左屏外，只露出部分篮口；长边与屏幕左缘平行，`basket_root.rotation.y = PI / 2`，篮口与桌面呈 90°。
- 表现层从真实 3D 篮口投影位置把商品抛向 2D 桌面。商品按 UID 错峰飞出，带抛物线、旋转和落地反馈；全部落地且空篮离开后解锁。
- 初始撒落使用 `TABLE_BOUNDS = Rect2(24,60,552,740)`，保留小关卡固定种子落点。
- 手动整理使用更大的 `DRAG_BOUNDS = Rect2(16,-92,888,892)`，再按商品旋转后的实际轮廓钳制；称重平台 `DRAG_SCALE_BLOCK` 向外扩张商品半径和 4px 间隙后作为禁放区。
- 超过 12 件时使用带随机抖动的网格、候选点和空间网格评分，减少中央高堆；精确遮挡与最近距离判断仍使用旋转包装几何。

### 2.3 商品尺寸、遮挡与命中

统一尺寸公式：

```text
final_size = tier_base_size × package_scale × product_scale
```

- `size=1` 普通款基础轮廓为 120×104，`size=2` 礼盒为 152×120，`size=3` 巨大款为 192×164。
- `package_scale` 是测试页或整单全局倍率，默认 1.5。
- `product_scale` 是每款商品独立的人工现实相对尺寸倍率，当前为 0.55～1.15。两轴共用同一标量，不拉伸 SVG，也不宣称真实毫米测量。
- 缺少 `product_scale` 的旧手工夹具默认 1.0；倍率只改变几何，不改变重量、价格、巨大/礼盒身份或旧台位成本。
- `BasketModel.hit_size()` 是视觉、阴影、Area2D 热区、曝光、遮挡、散布、SAT 和拖动边界的统一尺寸源。
- 每件商品有独立 `x / y / rot / layer`。`hit_test()` 按逆层序命中，不穿透上层；`hit_test_assisted()` 只为实际可拾取商品提供边缘输入余量。
- `exposure()` 使用 5×5 采样，`exposed_point()` 使用 9×9 采样寻找真实露出位置，并在同一组命中结果中优先选择离异物采样点更远的格子，避免浏览器指针量化后误中遮挡边缘。被遮盖商品仍参与聚堆完整性，但只有实际露出后才能直接按下拖动。
- 拿走上层后重新计算曝光，因此可以逐层整理和清空。

### 2.4 拖动与单击迁移

#### 自由拖动

- 桌面按下只建立拖动候选；指针移动超过 9px 后进入拖动态。
- 首次移动调用 `move_item()` 更新核心位置并提层，后续移动同步视觉位置；拖动途中不扫描聚堆。
- 松手调用 `finish_move()` 后重扫整张桌。取消交互时也结束拖动并按既有规则处理。
- 重叠点只命中实际露出的商品；被点击商品的旋转尺寸决定可拖动边界。

#### 单击飞到远处同款

- 未形成拖动的松开视为单击。
- `find_click_target(uid)` 查询同款未结算物品，包含被遮挡目标，排除自身和中心距离不超过 **220px** 的同款。
- 在剩余候选中选择中心距离最近者，等距按 UID 升序；目的地通过 `clamp_to_drag()` 按被点击商品尺寸校正。
- 有合法目标时，商品沿短抛物线飞到目标中心。飞行期间不提前修改核心坐标、不扫描聚堆，并锁定竞争桌面输入和自动提示。
- 到位回调最后调用 `finish_move(uid, destination, true)`，再提层和扫描；若形成合格堆，既有自动称重飞行立即接管。
- 没有目标或校正后落点与当前位置相同时，只播放 `tap_bounce()`，不改变核心坐标、层序或批次。

### 2.5 自由聚堆与自动称重

- 同款包装表面间距不超过 **18px** 时连通，可通过第三件传递连接；旋转矩形使用 SAT，不用圆心距离替代。
- 该同款的全部未结算物品必须形成**一个**连通分量，被遮挡商品也计入；拆成多个分量不会触发。
- 异款检测使用 `packages_near(member, foreign, 0.0)`：实际接触或重叠会阻断，精确贴边仍算接触；存在任意正净间隙即放行，不再要求 28px 隔离带。
- 多个同时合格的堆按首件 UID 进入 FIFO。上一批飞行结束后立即结算并启动下一批，无额外冷却。
- 单批基础飞行约 0.18 秒，错峰最多约 0.08 秒；LED、价签、装袋与下一批飞行自然重叠。
- POS 固定显示“聚堆自动称重”，不承担手动结算。屏幕双击不会触发结算。

### 2.6 连击、耐心与计分

- 连击窗口为 `combo_window_sec × 角色 combo_window_mult`；顶部 COMBO 标签同步核心值并有回弹动画，超时或换客清零。
- 当前顾客耐心为 `关卡基础耐心 × 角色 patience_mult × 难度倍率`，只在核心计算；暂停、倒货与换客时不推进。
- 耐心耗尽导致失败；无耐心关卡配置为 0。
- 每批按实际自动称重件数计价，保留批量、连击、完美奖励和主题小费公式。`bagged_items` 是实际称重件数，`bagged_groups` 是完成批次数。
- 礼盒和盲袋沿用各自配置与身份；巨大包装只改变尺寸档位和外观，不额外改变商品克重。

## 4. 可配置设计

配置位于 `data/`，由 `ConfigDB.runtime_config()` 合并关卡、难度与升级。

| 配置 | 作用 |
|---|---|
| `levels.json / customers` | 每关顾客数 |
| `levels.json / items` | 旧直接生成器兼容件数，不决定正式 manifest |
| `levels.json / snack_kinds / pool` | 款数与显式商品池 |
| `levels.json / pool_categories` | 按品类展开候选商品 |
| `levels.json / category_diverse` | 按品类轮流抽款 |
| `levels.json / overlap` | 初始散布集中度与旋转程度 |
| `levels.json / patience` | 每位顾客基础耐心，0 为不限时 |
| `levels.json / customer` | 行为主题与小费倍率 |
| `levels.json / features` | `gift`、`blind` 特殊物品 |
| `snacks.json / snacks` | 商品 ID、品类、名称、包装、克重、`product_scale`、配色与 SVG |
| `customers.json / customers` | 角色资料、头像、耐心与连击修正 |
| `difficulty.json` | 耐心、连击、自动提示及旧兼容字段 |
| `upgrades.json` | 电子秤速度升级；旧容量/吸附字段只作兼容 |

`snacks.json` 使用 `schema_version = 2`。`tools/make_snacks.py` 是当前 40 款配置和 120×120 SVG 的生成源，商品元组包含 `product_scale`；修改后应同步重新生成 JSON。包装文字转为矢量路径，避免 Godot SVG 导入忽略 `<text>`。生成脚本会覆盖对应文件。

`tools/make_customers.py` 生成 12 位角色配置与原创 SVG 头像。角色发现写入 `customers_discovered`，与零食图鉴分离；旧存档缺字段时按空图鉴处理。

主页测试入口支持关卡 1～20、轻松/标准/挑战、随机或固定 1～10 件、全局包装倍率 1.0～2.0、巨大款 0～2 种。测试局不写正式金币、星级、解锁、图鉴或难度设置。

## 5. 工作台 UI 与表现

逻辑分辨率为 **720×1280**。右侧 POS 与承重平台同轴紧凑排列，由短支架连接；底部五分之一为全宽收银员过道 `Rect2(0,1024,720,256)`，收银员站在 `(360,1152)`。

```text
┌──────────────────────────┐
│ 金币 / 关卡 / 顾客 / 暂停 │ 右上 COMBO │
│ 袋图标 / 已称重件数与批数 / 顶部进度   │
├──────────────────────────┤
│ 当前顾客 + 对话 + 耐心    │ 一体式 POS │
│ 横向排队等候区            │ 短支架     │
├──────────────────────────┤
│                          │ 承重平台   │
│  大面积自由分拣桌面       │ LED / 价签 │
│  拖动聚堆 / 单击迁移同款   │           │
│                          │           │
├──────────────────────────┤
│       全宽收银员过道 / 俯视人物动作     │
└──────────────────────────┘
```

- 顶部 HUD 集中营业信息、称重进度和 COMBO；底部旧操作栏、吸附、台位和冻结按钮已移除。
- POS 是自动称重状态提示，不再显示混品拒结或手动结算按钮。
- 桌面商品按包装顶面压缩绘制，带阴影、旋转和层序；拖动提高层级，单击迁移使用短桌面抛物线。
- 收银员有 idle、拿篮、分拣和称重反馈；动作由篮阶段与核心信号驱动。
- 自动称重演出为：整堆飞入电子秤 → LED 数字滚动 → 价签打印并飞向袋图标 → 装袋与收银音效。多批反馈可以重叠。
- 结果页显示星级、最高连击、用时、称重件数/批次数、奖励和金币；测试局结果返回测试设置。

## 6. 美术与音频

- **复古国潮小卖部 + 复古绿一体式电子秤**：暖色墙面、货架、俯视木桌、编织篮、搪瓷/纸质 UI、深棕描边和中文招牌感字体。
- 当前包含 **8 类 × 5 款，共 40 款原创商品**：膨化、糖果巧克力、饼干糕点、果冻布丁、坚果炒货、辣味卤味、果干蜜饯、饮料乳品。
- 枕式袋、自立袋、纸盒、铁盒、扭结糖纸、巧克力套封、撕膜杯、瓶和屋顶盒等包装只参考现实品类通用结构；名称、子品牌、文字和图形均原创。
- 不同商品通过独立 `product_scale` 呈现现实相对大小；巨大款额外带“巨”标识，不替换商品身份。
- 音效包括拾取、称重、打印、装袋、结账、完成和失败。Web 音频需首次用户交互解锁，听觉与音量仍需人工验收。

## 7. 架构：逻辑与渲染分离

```text
┌────────────────────────────────────────────────┐
│ 表现层 game/（Godot Node / Control）            │
│ 真实输入、Tween、音效、页面、POS 和 Web 只读桥   │
│ 单击 → find_click_target / finish_move          │
│ 拖动 → move_item / finish_move                  │
│ 每帧 → core.update(delta)                       │
├────────────────────────────────────────────────┤
│ 核心层 core/（纯 RefCounted，无 SceneTree）      │
│ GameState     顾客、聚堆 FIFO、自动称重与胜负    │
│ BasketModel   尺寸、SAT、曝光、连通堆与单击目标  │
│ TrayModel     当前批次与旧秤台兼容条目           │
│ LevelGenerator 逐客 manifest 与固定种子散布      │
│ ComboSystem / PatienceClock / ScoreSystem       │
├────────────────────────────────────────────────┤
│ 数据层 data/（JSON）                            │
│ levels / snacks / customers / upgrades / difficulty │
└────────────────────────────────────────────────┘
```

`BasketModel` 类名为兼容保留，职责是倒出后的桌面商品模型。core 不使用 `Node`、`SceneTree` 或 `Timer`，时间由表现层调用 `update(delta)` 推进。

主要信号包括：

- `batch_started`：表现层接管整堆飞入电子秤。
- `group_weighed`：驱动 LED、价签、装袋和进度；“group”指实际完整同款批次，不是三件组。
- `customer_served` / `customer_started`：驱动换客和下一次撒落。
- `combo_changed`、`level_completed`、`level_failed`，以及保留给旧兼容路径的拾取/退货信号。

动画状态与核心提交顺序是单击迁移的关键约束：桌面飞行完成回调必须位于旧动画状态恢复之后，再调用 `finish_move()`，避免旧回调覆盖新称重飞行的 `flying / interactive / z_index`。

## 8. Godot + Web 技术方案

| 项目 | 当前方案 |
|---|---|
| 引擎 | Godot 4.7.2，Compatibility / GL Compatibility |
| 分辨率 | 720×1280，`canvas_items` + `keep`，居中留边 |
| 导出 | 单线程 Web，输出 `build/web/index.html` |
| 输入 | 桌面鼠标与 Godot 输入事件；触屏真机待实测 |
| 存档 | 本地存档；Web 自动化使用全新 Chrome profile |
| 小程序 | 另有独立 Canvas 小工具；本轮四项调整未同步 |

### Web 自动化桥

仅当 URL 带 `?smoke=1` 时开启，`seed` 可指定固定种子。根节点定期向 `window.godotSmokeState` 发布只读 JSON，并在关键篮阶段补发，避免漏掉短动画。

快照包含页面、顾客与队列、倒货锁、篮口与出货点、桌面节点、旋转四角、可点露出位置、`product_scale`、`logical_size`、当前拖动 UID、单击遥测 `table_tap`、单击飞行 `click_flight_uid`、活动/等待批次、LED、价签、进度、布局、测试页弹窗实际位置与可见状态和存档摘要。
