# 《零食叮叮咚》游戏设计与实现说明（MVP v1.7）

> 当前版本：篮口俯视购物篮绕自身右侧长边在桌面左缘翻转 120°、翻转途中从篮内连续撒落、全部落地后回正 + 底部五分之一全宽收银员过道 + 拖动整理 + 双击聚合附近同款 + 一体式屏秤 + 顶部进度和动画连击。
>
> 美术方向：**C 复古国潮小卖部 + A 的电子秤**，保留 LED 数字滚动、价签打印和收银音效。
>
> 引擎：Godot 4.7.2 · Compatibility 渲染器 · Web 优先 · 20 关 MVP。

---

## 1. 游戏概述

**一句话概念**：在高位俯视的收银工作台前接待一列顾客，把购物篮右侧长边贴在桌面左缘，向桌面翻转 120° 并将零食从篮内撒到左桌，拖动整理相互遮挡的零食堆，单击或双击把同款分批送到右侧一体式屏秤，在 POS 上手动称重、打印价签、装袋结账。

| 项目 | 内容 |
|---|---|
| 品类 | 解压整理 + 点击分拣 + 轻经营 |
| 核心情绪 | 乱到齐、连点节奏、清空桌面完成感、收银 ASMR |
| 单局时长 | 常规关约 1～3 分钟；第 2 关 300 件为高密度配置，时长明显增加 |
| 操作 | 竖屏单手点击、双击与拖动 |
| 店名 | 零食叮叮咚（原创品牌，不使用真实门店品牌） |

### 核心循环

顾客排队 → 当前顾客的购物篮入场、倾斜并把零食倒到左桌 → 拖动整理或点击真实露出的零食 → 单击一件入秤 / 双击聚合附近同款 → 台上只保留同一种零食 → 点击 POS“称重结算” → 打印价签并装袋 → 桌面和台都空后结账 → 下一位顾客 → 服务完全部顾客后进入关卡结算。

**本版没有三连规则**：不凑三、不满三件自动消除，也没有“盘满且无三连即失败”。玩家自行决定每批称重的同款件数，单件也可以结算。

### 外循环

营业赚金币 → 永久升级称重台容量和电子秤速度 → 解锁新零食与顾客图鉴 → 挑战后续关卡与不同难度预设。

## 2. 核心规则

### 2.1 顾客队列

- 每关由 `customers` 位顾客组成，顶部显示“顾客 当前/总数”；后续最多三位排队顾客显示在当前顾客资料下方的横向队列区。
- 当前有 **12 位独立角色**，每人拥有唯一 ID、姓名、原创头像、性格、简介和台词；同一关卡队列不重复角色，排队头像直接读取各自配置，不再把同一类型 SVG 换个位置复用。
- 角色队列由独立 `customer_rng` 按种子生成，保留关卡普通/急性子/豪爽行为类型的编排，同时不改变 `layout_rng` 的购物篮生成序列。
- 任意时刻只处理当前顾客倒在桌面上的这一批零食。
- 当前顾客的桌面已空、称重台也已空，才视为该顾客结账完成。
- 最后一位顾客的桌面和称重台都清空后，关卡完成；只清空桌面但台上仍有零食时不会提前过关。
- 当前 20 关中，每位顾客的每件订单数量相同，因此整关总件数为 `customers × items`，开局即确定，进度分母不会随换客增加。
- 换顾客后生成新一批桌面零食，恢复基础台位和耐心；永久台位升级不会在顾客之间重复累加。正常操作界面没有吸附、临时“+台位”或冻结入口。
- 当前连击在换客时清零，全局最佳连击保留到关卡结算。

### 2.2 倒货、桌面散落与真实遮挡

- 每件零食有独立的 `x / y / rot / layer`，表示倒货后的桌面落点、旋转和遮挡层序。扩大后的桌面边界为 `TABLE_BOUNDS = Rect2(24, 60, 552, 1000)`，物品按旋转后的实际尺寸钳制在边界内；在 0.78 桌面缩放下，全局安全区约为 `(18.72, 446.8)` 到 `(449.28, 1226.8)`。
- 最终落点由固定种子的 `layout_rng` 生成：两个随机数之和形成偏向桌面中心的三角分布，新落点再与前 1～5 个落点之一形成接触偏移，并与独立随机点混合，模拟整篮倒下后的接触、旋转和相互堆叠。不使用不可复现的刚体物理。
- `overlap` 越大，散布范围越集中、旋转越明显；`layer` 同时决定绘制顺序和遮挡顺序。表现层把零食从同一篮口按 UID 轻微错位、错峰抛物线抛向这些最终落点，并加入落地旋转回弹、阴影和层序变化。
- 普通零食的旋转矩形热区为 **120×104**，大礼包为 **152×120**；核心遮挡采样、包装绘制和实际输入共用这套几何尺寸。桌面显示缩放为 **0.78**。
- 零食按包装顶面压缩绘制并带独立投影。购物篮与 `SortingTable` 是独立节点：购物篮先绕篮底枢轴倾转，每件零食在实际出货时才从篮口转移到桌面并飞向确定性落点；全部落地后空篮淡出、释放，随后才解锁输入。
- `hit_test(point)` 按逆层序查找，重叠位置只会命中该点最上层的零食，不会穿透选中下层。
- 表现层精细命中未命中时调用 `hit_test_assisted(point, 14)`，只给实际可拾取零食增加一圈输入余量；核心曝光和精确热区不变，辅助范围不会穿透高层或点中完全遮挡物。
- `exposure(uid)` 在目标自身旋转热区上做 5×5 曝光采样；曝光比例达到 0.12 才允许普通拾取。
- `exposed_point(uid)` 使用更密的 9×9 采样寻找真实可点击位置，供桌面和 Web 自动化复用，避免测试另写一套“看起来可点”的规则。
- 拿走上层物品后，下层曝光会重新计算；最高层始终可点，因此可以逐层清空。被盖物品的中心点不等于合法点击点，玩家必须点它实际露出的区域。
- 核心测试逐件计算旋转后的四个角，确保全 20 关、所有顾客的零食均位于扩大后的桌面边界内；另用占 2 格、旋转 27° 的大礼包验证四边极限拖动。桌边物品另有真实鼠标和 Chrome 拣入/退货测试。

#### 拖动整理

- 桌面按下只建立拖动候选，松开才执行单击入秤；指针移动超过 **9 像素**后进入拖动态，不会误把零食送入称重台。
- 首次拖动调用 `GameState.move_item()` 更新核心位置并提升到最上层，随后归一化层号，避免长期操作令 `z_index` 无限增长。视觉位置、命中测试和退货位置共用同一份核心数据。
- 拖动只整理位置与层序，不称重、不消耗台位。退货会回到该物品最后拖动后的桌面位置、旋转和层序。

#### 双击聚合

- 第一次单击立即入秤，不为等待双击而增加单击延迟。第二击根据第一击保存的商品 ID 和桌面中心，把 **220 半径内**实际露出的同款按“距离由近到远、距离相同按 UID”连续送入秤，多件飞入有 0.045 秒递增延迟。
- 聚合复用核心 `pick()`，因此不穿透遮挡、遵守剩余台位、揭示盲袋并更新连击和 LED；遇到首个无法拣入的候选即停止，**不自动称重结算**。
- 表现层同时支持 Godot 原生 `double_click` 和 **400ms / 24 像素**时空窗口兜底，避免 Web 或未来触屏平台未可靠提供原生标记时失效；拖动不会触发双击。

### 2.3 称重台与手动结算

- 点击可拾取零食后，该零食从桌面待分拣集合中移出并加入称重台，表现层播放飞行动画。
- `GameState.tray_weight()` 实时汇总台上各商品的配置克重与 `size`；拣入、双击聚合和退货后，LED 立即显示理论总重，不等待结算动画。
- 称重台按 `size` 占用格数：普通零食占 1 格，大礼包占 2 格。
- 台满只拒绝继续放入并提示，不直接判负。玩家可以先结算同款批次，或把台上物品退回桌面。
- 台上为空时，POS 拒绝结算，原因码为 `empty`。
- 台上含不同零食时，POS 拒绝结算，原因码为 `mixed`；按钮同时置灰并提示“请先整理同款”。
- 点击台上零食可逐件退货。退货恢复它最后记录的桌面位置、旋转和层序，连击清零，不判失败。
- 台上只剩同一种零食后，无论 1 件还是多件，都可点击“称重结算”。
- 手动结算后才会增加称重件数、批次数和收益，并播放 LED 重量、价签打印和装袋演出。
- 只有实际发生超容量拒放才记录 `had_tray_full`；玩家主动把称重台恰好放满，不会因此失去完美奖励。

### 2.4 连击与耐心

- 普通连续拾取在当前角色的连击窗口内累加，超时、退货或换客会清当前连击；窗口为基础 `combo_window_sec × 角色 combo_window_mult`。顶部右侧 COMBO 徽标同步显示当前值，连击达到 2 以上时以 1.12 倍峰值回弹，连续触发会替换旧动画而不叠加 Tween；超时后核心和标签同时清零。
- 底部旧 COMBO 栏和吸附、临时“+台位”、冻结按钮均已移除。双击聚合同款是保留的基础分拣操作，不是吸附道具；永久称重台容量升级也仍然保留。
- 当前顾客耐心为 `关卡基础耐心 × 角色 patience_mult`，只在 `GameState` 乘一次。急性子角色的倍率均小于 1（当前 0.82～0.90），普通/豪爽角色也有各自节奏，不再所有人共用固定数值。
- 大礼包占 2 格；盲袋底牌在生成时确定，首次拿到台上时揭示。
- 耐心耗尽会导致本关失败；暂停时表现层停止调用核心 `update(delta)`。
- 纯核心的旧吸附、临时台位和冻结 API 暂为兼容测试保留，没有生产 UI 入口，也不属于当前玩家流程。

### 2.5 称重演出

分拣阶段，LED 始终跟随 `tray_weight()` 显示当前理论总重。点击结算后，核心以该理论重量为基础做 0.95～1.05 的固定种子扰动，得到本批实际称重值；表现层再播放 LED 从 0 滚动到实际值并定格的演出。结算产生的空台刷新不会打断这次滚动，但新的拣入/退货会立即恢复实时重量显示。

零食飞入电子秤 → LED 重量数字滚动 → “滴”定格 → 价签“刺啦”打印 → 价签飞向购物袋 → 袋装音效与收银提示。称重演出只负责表现，实际入账由核心状态机在手动结算成功时一次性完成。

### 2.6 购物篮倒货与换客演出

核心在上一客桌面和台都空时同步推进队列并发出 `customer_started(customer_index, customer_id)`，核心逻辑不依赖 Tween。表现层收到信号后创建新 `BasketView` 和商品节点：购物篮先从台面下方入场，约 0.32 秒到位；随后绕 `BasketView.PIVOT = Vector2(300, 650)` 在约 0.28 秒内倾转到 `-0.78` 弧度。篮内商品采用独立紧凑摆位，只有实际出货时才脱离篮子，从当前篮口连续抛向核心预生成的桌面落点，避免大桌面坐标在入场时露出篮外。

出货间隔为 `min(0.075, 1.20 / max(1, count - 1))`：100 件会在约 1.2 秒窗口内连续倒出，单件桌面飞行约 0.42 秒，并带旋转回落、阴影和层序变化。最后一件完成后等待约 0.54 秒，再让空篮淡出撤走、释放节点并解锁输入。`_switching_customer` 覆盖入场、倾倒、空篮消失全程，锁定桌面、秤上和 POS 输入，并停止推进核心耐心与连击计时；`_pouring` 从倾转开始标记实际倒货阶段。最后一位完成时直接进入结算，不播放入场动画。桌面和 Chrome 均验证空篮消失前输入保持锁定，桌面另验证耐心暂停、全部零食落地和结束后桌面解锁。

- `items` 是**每位顾客**的零食件数，不再是三消组数。

### 3.1 星级评价

- ★：完成整关，即服务完全部顾客。
- ★★：无耐心关满足 `用时 ≤ 整关总件数 × 6 秒`；有耐心关满足当前结算所用的耐心比例 ≥ 40%。
- ★★★：满足 ★★，且最高连击 ≥ `ceil(整关总件数 × 0.65)`，并没有实际发生超容量拒放。

### 3.2 收益公式

按**实际手动称重批次**计价，不再按三件组计价：

```text
单件基础价 = 1.7 × (1 + 关卡 × 0.02)
批次基础价 = 单件基础价 × 本批件数
批量加成   = 批次基础价 × max(0, 本批件数 - 1) × 4%
连击加成   = 批次基础价 × min(结算时 combo × 5%, 50%)
批次收益   = round(批次基础价 + 批量加成 + 连击加成)
完美奖励   = 完成且没有实际超容量拒放时，累计称重收益 × 1.30
小费       = round(最高连击 × 2 × 关卡主题小费倍率)
过关金币   = 完美处理后的累计称重收益 + 小费
```

结算数据中的 `bagged_items` 是实际称重件数，`bagged_groups` 是玩家手动结算批次数，`return_count` 是台上退货次数。

## 4. 可配置设计

配置位于 `data/`，运行时在 `ConfigDB.runtime_config()` 中合并关卡、难度预设和设备升级。

| 配置 | 作用 |
|---|---|
| `levels.json / customers` | 每关顾客数 |
| `levels.json / items` | 每位顾客倒到桌面的零食件数 |
| `levels.json / snack_kinds / pool` | 品种数与显式可选零食池 |
| `levels.json / pool_categories` | 按品类自动展开全部候选商品；优先级高于默认商品池 |
| `levels.json / category_diverse` | 按品类轮流抽款，先覆盖所有品类，再补充同品类其他商品 |
| `levels.json / scatter_width / scatter_height` | 可选桌面散布尺寸，默认 500×680；第 2 关百件订单为 520×900 |
| `snacks.json / categories` | 品类 ID、名称及通用包装参考说明 |
| `snacks.json / snacks` | 商品 ID、品类、原创品牌/名称、包装模板、克重、配色、包装说明与 SVG |
| `levels.json / overlap` | 散布集中度与旋转程度 |
| `levels.json / patience` | 每位顾客基础耐心，0 为不限时 |
| `levels.json / customer` | 关卡行为主题与小费倍率；决定队列中普通/急性子/豪爽角色的编排 |
| `customers.json / customers` | 独立角色 ID、姓名、行为类型、性格、简介、台词和头像 |
| `customers.json / patience_mult` | 当前角色耐心倍率，只乘一次；急性子均小于 1 |
| `customers.json / combo_window_mult` | 当前角色连击窗口倍率 |
| `levels.json / features` | `gift`、`blind` 特殊物品 |
| `difficulty.json / tray_slots` | 基础称重台格数 |
| `difficulty.json / patience_scale` | 耐心倍率 |
| `difficulty.json / combo_window_sec` | 连击窗口 |
| `difficulty.json / magnet_charges` | 旧吸附兼容字段；当前正常操作界面不读取为可用道具入口 |
| `difficulty.json / auto_hint` | 停滞后自动高亮可分拣同款 |
| `upgrades.json` | 升级费用、等级上限和效果 |

`snacks.json` 使用 `schema_version = 2`。每款商品包含 `id / category / name / brand / mark / pack / weight / color / accent / package_note / svg`，后续新增商品只需补齐同结构配置及包装资源。`tools/make_snacks.py` 可重新生成当前 40 款配置和 120×120 SVG，运行需 `fontTools` 和项目内 `assets/fonts/ui_font.ttc`；包装文字被转换为矢量路径，避免 Godot SVG 导入忽略 `<text>`。脚本会覆盖对应生成文件，手工改动后不要无意中重跑覆盖。

`customers.json` 使用 `schema_version = 1`，12 位角色分别配置 `id / name / base_type / personality / description / lines / avatar / patience_mult / combo_window_mult`。`base_type` 只负责兼容关卡行为编排，显示与图鉴全部使用角色 ID。`tools/make_customers.py` 生成配置和 12 张 180×210 无文字原创 SVG 半身像；发型、配饰、肤色、服装和配色不同，不引用真实人物或第三方角色。运行脚本同样会覆盖对应生成文件。

顾客出现时立即调用 `SaveData.meet_customer()`，包括关卡第一位角色；发现记录写入 `customers_discovered`，与零食 `discovered` 分离。旧版 `user://save.json` 没有该字段时加载为空字典，无需迁移或清档。

三档预设：`relax` 8 台位/双倍耐心/4 秒连击/自动提示；`standard` 7 台位/3 秒连击；`challenge` 6 台位/0.8 倍耐心/2.5 秒连击。旧 `magnet_charges` 数值仍留在 JSON 供核心兼容测试使用，不产生吸附按钮。

`deadlock_protection` 字段目前只保留在配置中，没有额外重排逻辑；当前可清空性来自逐层曝光、台上退货和同款任意批量手动结算。

- 结算页显示星级、最高连击、用时、称重件数/批次数、退货次数、完美奖励、小费与金币。

## 7. 架构：逻辑与渲染分离

```text
┌────────────────────────────────────────────────┐
│ 表现层 game/（Godot Node / Control）            │
│ 真实输入、Tween、音效、POS、队列、页面和 Web 桥 │
│ 点击 → core.pick(uid) / gather_nearby_at(...)   │
│ 拖动 → core.move_item(uid, point, front)        │
│ 退货 → core.return_item(uid)                    │
│ POS   → core.settle_scale()                    │
│ 每帧 → core.update(delta)                      │
├────────────────────────────────────────────────┤
│ 核心层 core/（纯 RefCounted，无 SceneTree）      │
│ GameState     状态机、顾客队列、胜负与无 UI 的兼容道具 API │
│ BasketModel   桌面边界、拖动提层、命中、曝光与位置恢复 │
│ TrayModel     容量、同款检查与台上条目           │
│ ComboSystem   连击窗口                         │
│ PatienceClock 耐心与旧冻结兼容接口                │
│ ScoreSystem   星级、批次价格与结算               │
│ GameRNG       固定种子随机                      │
├────────────────────────────────────────────────┤
│ 数据层 data/（JSON）                            │
│ levels / snacks / customers / upgrades / difficulty │
└────────────────────────────────────────────────┘
```

`BasketModel` 类名暂时保留以兼容既有核心接口，但职责已经是“购物篮倒出后的桌面零食模型”，不再表示只能在篮内拣选。

主要核心信号：

- `snack_picked` / `snack_returned`：驱动物品飞行与退货。
- `tray_changed`：刷新承重台布局、POS 状态和 LED 实时理论重量。
- `group_weighed`：驱动 LED、价签、装袋和进度；名称保留，但“group”指任意件数的手动批次，不是三件组。
- `customer_served` / `customer_started`：驱动换客提示、独立角色队列和下一次购物篮倒货；`customer_started` 第二参数为角色 ID。
- `combo_changed`、`pick_rejected`、`checkout_rejected`、`level_completed`、`level_failed`。

约束：

- core 不使用 `Node`、`SceneTree` 或 `Timer`，时间统一由表现层 `update(delta)` 推进。
- 逻辑物品以 UID 标识，表现层点击只传命令，不自行修改数量、价格或胜负状态。
- `layout_rng` 专门生成顾客桌面最终落点，`customer_rng` 独立生成不重复的角色队列，`rng` 用于称重扰动等结算随机；玩家采用不同分批方式不会重新随机后续顾客布局或角色。倒货起点的 UID 错位不消耗玩法 RNG。
- 迁移小程序时仍需平台表现层和适配层；当前只完成架构准备，不代表已经支持小程序导出。

### Web 自动化桥

桥不提供拾取、退货、结算、金币或存档修改接口。`tools/web_smoke.py` 只读取快照并通过 Chrome DevTools Protocol 发送真实鼠标事件；点击坐标根据 canvas 实际矩形、等比缩放和居中留边偏移换算到 720×1280 逻辑坐标。
