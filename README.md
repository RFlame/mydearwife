# 零食叮叮咚

复古国潮小卖部收银分拣解压游戏 · 20 关 MVP · Godot 4.7.2 · Web 优先

当前玩法：**顾客排队 → 左屏外固定 90° 购物篮撒落 → 拖入上方四个椭圆集货区 → 同款全部同区后称重 → 装袋结账**。桌面单击只原地轻跳；点击区内未锁定零食会退回拖动前的位置。区域允许混放，但混放、跨区分拆或同款仍有零食留在桌面/称重台时都不会结算。POS 的“自动结算”按钮可切换模式：开启时完整区域自动称重；关闭时完整区域保持等待，在屏幕任意位置双击后，所有满足条件的区域按 FIFO 依次称重。

工作台采用高位俯视布局：篮体位于左屏外，只露出部分篮口，长边与屏幕左缘平行，`basket_root.rotation.y` 固定为 `PI / 2`，零食从真实 3D 篮口投影位置抛向 2D 桌面。右侧 POS 与承重平台同轴紧凑排列，由短支架连接成一体设备；底部五分之一为全宽收银员过道 `Rect2(0,1024,720,256)`，收银员站在 `(360,1152)`。初始撒落仍使用 `Rect2(24,60,552,740)`，保留小关卡固定种子落点；手动拖动扩展到整张台面，仅按旋转后的包装四角排除称重平台和收银员过道。四个无边框椭圆优先布置在上方两排，桌面顶部不再放置玩法文案。多区同时集齐时共用同一 FIFO 队列串行占秤，已排队区域锁定，避免退货与称重争抢物品。

商品配置包含 **8 个品类、每类 5 款，共 40 款原创零食包装**。第 2 关为 **3 位顾客 × 每位 6 件、3 款**，整关共 18 件，不再使用百件订单。

普通零食显示与精确热区同步放大，桌面缩放为 0.78，并保留不穿透遮挡的边缘辅助点击。按住拖动可整理零食或投入椭圆区；拖放命中使用真实椭圆内部，包围盒角部不会误投放。不超过 12 件的小篮保留原固定种子生成路径；超过 12 件时使用带随机抖动的全桌面网格和候选点，减少中央高堆并让更多零食露出可点。倒货与换客动画期间锁定输入并暂停耐心。

顾客系统包含 **12 位原创独立角色**，每位有不同头像、姓名、性格、简介、台词及耐心/连击窗口修正；当前 20 关的同一队列不会重复角色。主页“顾客图鉴”记录已接待角色，旧存档缺少该字段时自动按空图鉴处理。

## 核心操作

1. 等购物篮撒落且空篮消失后，从桌上**实际露出的**零食开始拖动；重叠点只命中实际露出的物品。
2. 把零食拖入任一四角椭圆区。桌面单击只轻跳，不会直接入秤；椭圆包围盒外的角部不属于落区。
3. 同一区域可以暂时混放。点击区内未锁定零食可退回拖动前的位置，再重新整理。
4. 只有当前顾客的某一同款**全部位于同一个区域**时，该区域才进入称重队列；混放、跨区、桌上或秤上仍有同款都不会触发。
5. POS 默认显示“自动结算：开”，完整区域会立即开始排队称重。点击切换为“自动结算：关”后，完整区域留在原地；在屏幕任意位置双击，会重新检测四区并将所有满足条件的区域按 FIFO 依次称重，无需逐区点击。
6. 多区共用同一串行队列，每批完成称重、LED 定格和价签弹出后处理下一批；已排队区域会锁定。切回自动模式会启动已经等待的完整区域。
7. 桌面、四区、等待队列和称重台全部清空后当前顾客结账。服务完全部顾客后进入关卡结算；耐心耗尽才会失败。

## 配置调平衡（不改代码）

- `data/levels.json`：`customers` 顾客数、`items` 每客件数、`snack_kinds/pool` 品种、`pool_categories` 品类池、`category_diverse` 分类均衡抽取、`overlap` 遮挡、`scatter_width/scatter_height` 散布范围、`patience` 每客耐心、`customer` 主题、`features` 大礼包/盲袋。
- `data/snacks.json`：schema v2；`categories` 定义 8 个品类，`snacks` 定义每款的 ID、品类、原创品牌/名称、包装模板、克重、配色、包装说明和 SVG 路径。新增商品可手改 JSON，或扩展 `tools/make_snacks.py` 后重新生成。包装只参考现实品类的通用结构和配色习惯，不复制真实品牌、商标、角色或标志性包装。
- `data/customers.json`：12 位角色的 ID、姓名、行为类型、性格、简介、台词、独立头像、`patience_mult` 和 `combo_window_mult`。`base_type` 保留普通/急性子/豪爽关卡编排与小费主题；实际人物由独立角色 RNG 确定，同关队列不重复。可通过扩展 `tools/make_customers.py` 重新生成配置和原创 SVG。
- `data/difficulty.json`：`relax` 8 台位/双倍耐心/自动提示，`standard` 7 台位，`challenge` 6 台位/0.8 倍耐心；还可配置连击窗口。旧 `magnet_charges` 仅为核心兼容字段，正常界面没有吸附入口。
- `data/upgrades.json`：升级页只展示永久称重台容量和电子秤速度两项；旧吸附配置暂为兼容数据，不出售也不显示。
- 当前每位顾客使用相同 `items`，整关总件数为 `customers × items`；若未来支持逐客不同件数，需要改为预生成队列后求和。
- `deadlock_protection` 目前仅为保留配置字段，没有额外重排逻辑。

完整规则、数值表、计分公式与架构见 [`docs/design_doc.md`](docs/design_doc.md)。
