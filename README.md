# 零食叮叮咚

复古国潮小卖部收银分拣解压游戏 · 20 关 MVP · Godot 4.7.2 · Web 优先

当前玩法：**顾客排队 → 购物篮把零食倒到左桌 → 拖动整理 / 单击入秤 / 双击聚附近同款 → 手动称重 → 台上退货 → 逐客结账**。没有三消或三件门槛，单件同款也能在 POS 上手动结算。

工作台采用高位俯视布局：新顾客的购物篮从完全位于左屏外的位置水平进入，与桌面左缘平行拿起，再以自身右侧长边为轴贴着桌缘向桌面翻转 **120°**。长边保持竖直，短边经历抬起、侧立和倾向桌面的投影变化；零食在翻转途中就从各自篮内实时位置连续抛出，120° 保持到全部落地后，空篮翻回 0° 再淡出释放。右侧 POS 与承重平台同轴紧凑排列，由短支架连接成一体设备；顾客资料适当收窄，排队等候显示在其下方。底部五分之一为全宽收银员过道 `Rect2(0,1024,720,256)`，收银员站在 `(360,1152)`，带 idle、拿篮伸手、分拣和称重庆祝动画。顶部 HUD 集中显示袋图标、称重进度和带动画的 COMBO，底部旧操作栏及吸附、临时台位、冻结入口已移除。左侧真实分拣安全区为 `Rect2(24,60,552,740)`，在桌面缩放 0.78 下全局约为 `(18.72,446.8)` 到 `(449.28,1024)`，不会伸入收银员过道。零食拣入或退回时，LED 会立即显示当前台上的理论总克重。

商品配置包含 **8 个品类、每类 5 款，共 40 款原创零食包装**。第 2 关为 **3 位顾客 × 每位 100 件**，每份订单包含 16 款商品并覆盖全部 8 类，整关共 300 件。

操作手感已针对密集桌面调整：普通零食显示与精确热区同步放大，桌面缩放为 0.78，并增加不穿透遮挡的边缘辅助点击。按下后拖动超过 9 像素可整理零食并提升其层级；单击立即将一件送入秤，紧接着的第二击会把中心半径 220 内实际露出的同款连续送入秤，受台位容量限制且不自动结算。倒货与换客动画期间锁定分拣和 POS 输入，并暂停耐心；空篮完全消失后才恢复操作。

顾客系统包含 **12 位原创独立角色**，每位有不同头像、姓名、性格、简介、台词及耐心/连击窗口修正；当前 20 关的同一队列不会重复角色。主页“顾客图鉴”记录已接待角色，旧存档缺少该字段时自动按空图鉴处理。

## 核心操作

1. 购物篮倒货后，点击桌上**实际露出的**零食，把它放上称重台；重叠点只命中最上层物品，LED 立即累加该商品克重。
2. 按住并拖动可整理桌面，所拖零食会提升到最上层；双击会把首次点击位置附近 220 半径内实际露出的同款连续送入秤，不自动结算。
3. 台上可放任意件数同款。若混入了不同零食，点击台上零食逐件退回拖动后的桌面位置，LED 同步减去对应克重。
4. 台上只剩同款后，点击右上方一体式屏秤 POS 屏幕上的“称重结算”；1 件也可以结算。
5. 桌面与称重台都清空后当前顾客结账，下一只购物篮入场并倒货；动画结束后才能继续分拣。服务完全部顾客后进入关卡结算。
6. 台满不直接失败，可先结算或退货；耐心耗尽才会失败。

## 配置调平衡（不改代码）

- `data/levels.json`：`customers` 顾客数、`items` 每客件数、`snack_kinds/pool` 品种、`pool_categories` 品类池、`category_diverse` 分类均衡抽取、`overlap` 遮挡、`scatter_width/scatter_height` 散布范围、`patience` 每客耐心、`customer` 主题、`features` 大礼包/盲袋。
- `data/snacks.json`：schema v2；`categories` 定义 8 个品类，`snacks` 定义每款的 ID、品类、原创品牌/名称、包装模板、克重、配色、包装说明和 SVG 路径。新增商品可手改 JSON，或扩展 `tools/make_snacks.py` 后重新生成。包装只参考现实品类的通用结构和配色习惯，不复制真实品牌、商标、角色或标志性包装。
- `data/customers.json`：12 位角色的 ID、姓名、行为类型、性格、简介、台词、独立头像、`patience_mult` 和 `combo_window_mult`。`base_type` 保留普通/急性子/豪爽关卡编排与小费主题；实际人物由独立角色 RNG 确定，同关队列不重复。可通过扩展 `tools/make_customers.py` 重新生成配置和原创 SVG。
- `data/difficulty.json`：`relax` 8 台位/双倍耐心/自动提示，`standard` 7 台位，`challenge` 6 台位/0.8 倍耐心；还可配置连击窗口。旧 `magnet_charges` 仅为核心兼容字段，正常界面没有吸附入口。
- `data/upgrades.json`：升级页只展示永久称重台容量和电子秤速度两项；旧吸附配置暂为兼容数据，不出售也不显示。
- 当前每位顾客使用相同 `items`，整关总件数为 `customers × items`；若未来支持逐客不同件数，需要改为预生成队列后求和。
- `deadlock_protection` 目前仅为保留配置字段，没有额外重排逻辑。

完整规则、数值表、计分公式与架构见 [`docs/design_doc.md`](docs/design_doc.md)。
