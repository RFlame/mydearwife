# 零食叮叮咚

复古国潮小卖部收银分拣解压游戏 · 20 关 MVP · Godot 4.7.2 · Web 优先

当前玩法：**顾客排队 → 左屏外固定 90° 购物篮撒落 → 桌面自由拖动聚堆 → 同款全部连通且周边无异款后自动称重 → 装袋结账**。同款包装表面间距不超过 18 个桌面逻辑像素时连通；该同款的全部未结算物品必须形成一个连通分量，且堆内任一成员周边 28 像素内不能出现异款。被遮挡物品也参与完整性检测，曝光只决定能否直接拖动。单击只原地轻跳，拖动途中不扫描，松手或取消拖动后才检测；POS 固定显示“聚堆自动称重”，不再有固定区域、区域退货、自动/手动切换或任意位置双击结算。

工作台采用高位俯视布局：篮体位于左屏外，只露出部分篮口，长边与屏幕左缘平行，`basket_root.rotation.y` 固定为 `PI / 2`，零食从真实 3D 篮口投影位置抛向 2D 桌面。右侧 POS 与承重平台同轴紧凑排列，由短支架连接成一体设备；底部五分之一为全宽收银员过道 `Rect2(0,1024,720,256)`，收银员站在 `(360,1152)`。初始撒落仍使用 `Rect2(24,60,552,740)`，保留小关卡固定种子落点；手动拖动扩展到整张台面，仅按旋转后的包装四角排除称重平台和收银员过道。多个同时合格的聚堆按首件 `uid` 确定 FIFO，使用零冷却连续批次：上一批飞行结束后立即结算并启动下一批，飞行、LED、价签和装袋反馈自然重叠。

商品配置包含 **8 个品类、每类 5 款，共 40 款原创零食包装**。正式订单按每位顾客独立随机：普通款每种 **1～20 件**，巨大款从当客已选种类中随机 **0～2 种、每种 1～2 件**，巨大包装替换同款普通包装而不额外增加种类。第 1～20 关的当客零食种类数严格递增为 **2～21 款**；第 2 关的固定测试夹具仍可使用 3 款 × 每款 2 件，但不再是正式订单的固定件数。普通与巨大包装默认整体为旧版 **1.5 倍**，测试页可调整包装倍率。

普通零食显示与精确热区同步放大，桌面缩放为 0.78，并保留不穿透遮挡的边缘辅助点击。普通 `size=1`、礼盒 `size=2`、巨大 `size=3` 共用 `BasketModel.hit_size()`；最终尺寸为基础轮廓 × `package_scale`，巨大款带“巨”标识，倍率只改变几何，不额外改变重量或旧台位成本。按住拖动可在整张桌面自由整理；旋转包装使用真实轮廓进行连通与异款隔离检测，包围盒或圆心距离不会替代该判断。不超过 12 件的小篮保留原固定种子生成路径；超过 12 件时使用带随机抖动的全桌面网格和候选点，减少中央高堆并让更多零食露出可点。空间网格保留精确 5×5 遮挡评分与最近中心距离；候选点按订单规模使用 12/6/4 个，避免极限订单逐项扫描。倒货与换客动画期间锁定输入并暂停耐心。

顾客系统包含 **12 位原创独立角色**，每位有不同头像、姓名、性格、简介、台词及耐心/连击窗口修正；当前 20 关的同一队列不会重复角色。主页“顾客图鉴”记录已接待角色，旧存档缺少该字段时自动按空图鉴处理。

主页另有可见的 **“玩法测试 · 难度 / 数量 / 包装大小”** 入口。测试页支持关卡 1～20、轻松/标准/挑战、普通款随机或固定 1～20 件、包装倍率 1.0～2.0、巨大款 0～2 种；测试局跳过顾客图鉴发现、金币/星级/解锁保存和正式难度设置，完成后返回测试设置，可重试或退出而不污染正式存档。

## 核心操作

1. 等购物篮撒落且空篮消失后，从桌上**实际露出的**零食开始拖动；重叠点只命中实际露出的物品。
2. 把同款零食拖到相互接触或接近的位置。同款包装表面间距不超过 18 像素即连通，可通过第三件传递连接；旋转包装按真实轮廓计算。
3. 该同款的全部未结算物品必须形成**一个**连通分量；被遮挡物品也计入。同款被拆成多个分量时不会触发。
4. 合格堆内任一成员周边 28 像素内出现异款会阻断自动称重；把异款拖开后，松手会重扫桌面并释放已解除阻断的堆。
5. 单击只原地轻跳；拖动途中不扫描，松手或取消拖动后才检测。POS 为静态“聚堆自动称重”提示，屏幕任意位置双击不会触发结算。
6. 多个同时合格的堆按首件 `uid` 进入 FIFO。单批基础飞行 0.18 秒、错峰最多 0.08 秒；飞行结束后同帧结算并启动下一批，无额外冷却。上一批的 LED、价签和装袋尾部与下一批飞行并行。
7. 桌面、活动批次、等待队列和兼容秤台全部清空后当前顾客结账。服务完全部顾客后进入关卡结算；耐心耗尽才会失败。

## 配置调平衡（不改代码）

- `data/levels.json`：`customers` 顾客数、`items` 旧直接生成器兼容件数、`snack_kinds/pool` 品种、`pool_categories` 品类池、`category_diverse` 分类均衡抽取、`overlap` 遮挡、`scatter_width/scatter_height` 散布范围、`patience` 每客耐心、`customer` 主题、`features` 大礼包/盲袋。正式订单以逐客清单为准，不再由 `items` 决定正式总件数。
- `data/snacks.json`：schema v2；`categories` 定义 8 个品类，`snacks` 定义每款的 ID、品类、原创品牌/名称、包装模板、克重、配色、包装说明和 SVG 路径。新增商品可手改 JSON，或扩展 `tools/make_snacks.py` 后重新生成。包装只参考现实品类的通用结构和配色习惯，不复制真实品牌、商标、角色或标志性包装。
- `data/customers.json`：12 位角色的 ID、姓名、行为类型、性格、简介、台词、独立头像、`patience_mult` 和 `combo_window_mult`。`base_type` 保留普通/急性子/豪爽关卡编排与小费主题；实际人物由独立角色 RNG 确定，同关队列不重复。可通过扩展 `tools/make_customers.py` 重新生成配置和原创 SVG。
- `data/difficulty.json`：`relax` 8 台位/双倍耐心/自动提示，`standard` 7 台位，`challenge` 6 台位/0.8 倍耐心；还可配置连击窗口。旧 `magnet_charges` 仅为核心兼容字段，正常界面没有吸附入口。
- `data/upgrades.json`：升级页只出售电子秤速度；旧称重台容量与吸附配置仅为存档/核心兼容数据，自由聚堆没有台位格数容量，正常界面不出售这些升级。
- 正式局每位顾客独立生成轻量订单清单，普通款每种 1～20 件；巨大款从当客种类中选 0～2 种、每种 1～2 件并替换普通包装。测试局可固定普通款数量和巨大种数；整关 `total_items` 为所有顾客清单长度之和，不再使用“首客件数 × 客数”。
- `deadlock_protection` 目前仅为保留配置字段，没有额外重排逻辑。

完整规则、数值表、计分公式与架构见 [`docs/design_doc.md`](docs/design_doc.md)。
